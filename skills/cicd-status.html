CLI local para ver el estado del pipeline registrado: últimos builds, tiempos por stage o job, cobertura trend, último deploy por entorno y enlaces a la plataforma (Azure DevOps o GitHub Actions, según cicd.platform). Para Fase 0 (sin pipeline): muestra recordatorio de deploy manual.

REGLAS CRÍTICAS

  • Leer _hilo/ESTADO_PROYECTO.json.infraestructura.cicd PRIMERO (objeto { plataforma, pipelines[] }). Sin pipelines[] → no hay pipeline configurado.
  • Resolver la plataforma antes de consultar nada con resolve('cicd.platform') (cicd.plataforma del Hilo y, si falta, ecosystem.config.json → cicd.platform; .claude/CONFIGURACION.md §Resolución). Azure DevOps y GitHub se consultan con herramientas distintas; el formato de salida es el mismo.
  • Si fase = 0: NO consultar Hub MCP. Solo recordar deploy manual.
  • Si fase ≥ 1: intentar tool MCP get_cicd_status. Si el Hub no responde, fallback directo a la plataforma: /_apis/build/builds (Azure DevOps) o gh run list (GitHub).
  • Modo --watch opcional para polling cada 30s (en GitHub, gh run watch sobre la run en curso).
  • Solo lectura: este comando NUNCA encola, despacha ni aprueba nada.

1. Detectar configuración CI/CD del proyecto

$estado  = Get-Content "_hilo/ESTADO_PROYECTO.json" -Raw | ConvertFrom-Json
$cicdRaw = $estado.infraestructura.cicd

# Forma canónica: OBJETO { plataforma, pipelines[] } (la escribe /cicd-init FASE 4). Compat: array suelto.
$pipelines  = if ($cicdRaw -is [array]) { @($cicdRaw) } elseif ($cicdRaw -and $cicdRaw.pipelines) { @($cicdRaw.pipelines) } else { @() }
$plataforma = if ($cicdRaw -isnot [array] -and $cicdRaw -and $cicdRaw.plataforma) { "$($cicdRaw.plataforma)" } else { $null }
if (-not $plataforma -and (Test-Path "ecosystem.config.json")) {
    $plataforma = (Get-Content "ecosystem.config.json" -Raw | ConvertFrom-Json).cicd.platform
}
$esGitHub = ($plataforma -eq 'github-actions')

if ($pipelines.Count -eq 0) {
    Write-Host "ℹ️  No hay pipeline CI/CD configurado en este proyecto."
    Write-Host "   Ejecuta /cicd-init para configurar (Fase 0/1/2)."
    exit 0
}

# R25: pipelines[] tiene una entrada por ENTRYPOINT (1 pipeline = 1 entrypoint). Por defecto mostrar TODOS;
# con --entrypoint <slug> filtrar a uno. (NO usar Out-GridView: el comando corre headless.)
if ($Entrypoint) { $pipelines = @($pipelines | Where-Object { $_.entrypoint -eq $Entrypoint -or $_.slug -eq $Entrypoint }) }
# Repetir las secciones 2-4 (builds, stages/jobs, drift) POR CADA $pipeline de $pipelines, encabezando con
# su entrypoint + tipo + serverType (app/svc) para distinguir Web / API / Console en el output.

Campos de cada entrada que usa este comando: entrypoint, slug, tipo, serverType, pipelineId (id de definición en Azure DevOps · nombre del fichero del workflow en GitHub, ej. cd-web.yml), yamlFile, url, fase, stages (stages de Azure · jobs de GitHub), stack, ultimoBuildStatus.

1.5 Drift de plantilla (sello del YAML vs versión instalada)

Si existe el YAML del pipeline, comprobar si el template del stack cambió desde que se generó. El YAML lleva un sello en la cabecera (# Ovillo cicd-architect <stack> @ vX.Y.Z (tpl <hash12>) gen <fecha>, puesto por /hv:cicd-init FASE 2.8). El token tpl <hash12> es el hash de contenido del .yml.template del stack, NO el zip-sha del ecosistema: así el drift solo salta cuando el template de TU stack cambió realmente, no en cada release. Se recomputa con el mismo helper que usó /hv:cicd-init (Get-TemplateStamp.ps1) y se compara. Los tokens de stack github-* (github-dotnet, github-vue, github-nettool, github-reusable, github-dotnet-fase1) los conoce el mismo helper.

Sellos en formato antiguo zip <sha12> (pipelines generados con una versión anterior de la plantilla): no se evalúa drift cosmético; se sugiere re-render (Opción 4) para migrarlos a tpl <hash>.

# R25: con >1 entrypoint hay varios ficheros -> comprobar drift en CADA uno
$yamls = if ($esGitHub) {
    Get-ChildItem -File .github/workflows/*.yml -ErrorAction SilentlyContinue | Where-Object { (Get-Content $_.FullName -TotalCount 8) -match 'Ovillo cicd-architect' }
} else {
    Get-ChildItem -File azure-pipelines*.yml -ErrorAction SilentlyContinue
}
foreach ($yf in $yamls) {
    $yamlPath = $yf.FullName
    Write-Host "  -- $($yf.Name) --"
    $head = Get-Content $yamlPath -TotalCount 8
    $stampLine = $head | Where-Object { $_ -match 'Ovillo cicd-architect' } | Select-Object -First 1

    $instVer = $null
    if (Test-Path "_hilo/VERSION.json") {
        $instVer = (Get-Content "_hilo/VERSION.json" -Raw | ConvertFrom-Json).installedVersion
    }
    $helper = "$env:CLAUDE_PLUGIN_ROOT/skills/cicd-architect/templates/Get-TemplateStamp.ps1"   # plugin hv@ovillo

    if (-not $stampLine) {
        Write-Host "[!] El pipeline no tiene sello de plantilla (generado con una version anterior de /cicd-init)."
        Write-Host "    Regenerar: /cicd-init -> Opcion 4 (re-render + self-check)."
    }
    elseif ($stampLine -match 'tpl\s+inline') {
        Write-Host "[i] Pipeline inline (Fase 1 minimal, sin .template): drift de plantilla no aplicable."
    }
    elseif ($stampLine -match 'tpl\s+([0-9a-f]{6,64})') {
        $stampHash = $Matches[1]
        $stack = if ($stampLine -match 'cicd-architect\s+(\S+)\s+@') { $Matches[1] } else { $null }
        $curHash = $null
        if ($stack -and (Test-Path $helper)) {
            try {
                $curHash = (& $helper -Stack $stack 2>$null | Select-Object -Last 1)
                if ($LASTEXITCODE -ne 0) { $curHash = $null }
            } catch { $curHash = $null }
        }
        if (-not $curHash) {
            Write-Host "[i] Sello hash-de-template (tpl $stampHash) pero no se pudo recomputar (helper ausente o stack '$stack' desconocido)."
            Write-Host "    Plantilla instalada: v$instVer. Ante la duda: /cicd-init -> Opcion 4."
        }
        elseif ($curHash -eq $stampHash) {
            Write-Host "[OK] Pipeline al dia con la plantilla instalada (sin drift; tpl $stampHash)."
        }
        else {
            Write-Host "[!] DRIFT de plantilla: el template del stack '$stack' cambio desde que se genero el YAML."
            Write-Host "      Sello del pipeline: tpl $stampHash"
            Write-Host "      Template actual:    tpl $curHash  (v$instVer)"
            Write-Host "    El pipeline puede no incluir lo ultimo (reglas/gates/steps nuevos)."
            Write-Host "    Accion: /cicd-init -> Opcion 4 (re-render COMPLETO) + self-check (FASE 2.8)."
        }
    }
    elseif ($stampLine -match 'zip\s+[0-9a-f]{6,40}') {
        Write-Host "[i] Sello en formato antiguo (zip-sha de una version anterior)."
        Write-Host "    Re-render (/cicd-init -> Opcion 4) para migrarlo a hash-por-template."
    }
    else {
        Write-Host "[i] Sello presente pero sin token de hash reconocible: $stampLine"
    }
}

Mostrar este aviso ANTES del listado de builds. Es informativo (no bloquea). Ver runbook _patron/08_CICD/RUNBOOK_ACTUALIZAR_PIPELINE.md. En GitHub, la composite action y el reusable workflow llevan su propio sello (github-action-*, github-reusable): comprobarlos también si existen.

Fallback si el Hub no responde — Azure DevOps

Si tool MCP falla (Hub offline, conectividad) y plataforma = azure-pipelines, consultar Azure DevOps directamente:

# [bloque TLS 1.2+ R2]
$builds = Invoke-RestMethod -Uri "$adoUrl/$proj/_apis/build/builds?definitions=$pipelineId&`$top=10&api-version=6.0" -UseDefaultCredentials
# timeline del último build OK: GET .../_apis/build/builds/<id>/timeline?api-version=6.0 -> records type=Stage (startTime/finishTime)
# ... formatear tabla similar al output anterior

Mostrar al usuario: ⚠️ Hub MCP no responde — datos de Azure DevOps directo (limitados, sin cobertura trend agregada).

Fallback si el Hub no responde — GitHub Actions

Con plataforma = github-actions, la fuente directa es gh (GitHub CLI autenticado; el pre-flight de /hv:cicd-init ya lo comprueba). $wf es el nombre del fichero del workflow (pipelineId, ej. cd-web.yml).

repo=$(gh repo view --json nameWithOwner --jq .nameWithOwner)

# Últimos N builds del workflow (una run por push / PR / dispatch). Duración = updatedAt - createdAt.
gh run list --workflow "$wf" --limit 10 \
  --json databaseId,number,status,conclusion,event,headBranch,headSha,createdAt,updatedAt,url,displayTitle

# Tiempo por job del último build OK (los jobs son los "stages": Build, Quality record, Deploy dev/pre/pro)
gh run view <databaseId> --json jobs --jq '.jobs[] | [.name, .conclusion, .startedAt, .completedAt] | @tsv'

# Último deploy por entorno: GitHub crea un deployment por cada job con `environment:`; su status enlaza la run
for env in dev pre pro; do
  dep=$(gh api "repos/$repo/deployments?environment=$env&per_page=1" --jq '.[0] | "\(.id)\t\(.sha[0:7])\t\(.created_at)\t\(.ref)"')
  [ -n "$dep" ] && gh api "repos/$repo/deployments/${dep%%$'\t'*}/statuses" --jq '.[0] | "\(.state)\t\(.log_url)"'
done

# Runs paradas esperando aprobación de environment (reviewers de pre/pro)
gh run list --workflow "$wf" --status waiting --json databaseId,url,displayTitle
gh api "repos/$repo/actions/runs/<databaseId>/pending_deployments" \
  --jq '.[] | {env: .environment.name, reviewers: [.reviewers[].reviewer.login]}'

Mapeo de estados: conclusion success → ✅ OK · failure → ❌ FAIL · cancelled → ⚪ CANCEL · status in_progress/queued → ⏳ · waiting → ⏸ aprobación pendiente. Deployment state: success / failure / in_progress / waiting / inactive (sustituido por un deploy posterior).

Mostrar al usuario: ⚠️ Hub MCP no responde — datos de GitHub directo (sin cobertura trend agregada; el Hub la calcula desde los QR). Si gh no está autenticado: imprimir la URL https://github.com/<owner>/<repo>/actions/workflows/<wf> y salir con aviso.

3. Modo --watch

Si el usuario invoca /hv:cicd-status --watch:

while ($true) {
    Clear-Host
    # Re-ejecutar el flujo de mostrar estado
    & $estadoCicdScript
    Write-Host ""
    Write-Host "🔄 Refresh cada 30s. Ctrl+C para salir." -ForegroundColor DarkGray
    Start-Sleep -Seconds 30
}

En GitHub, si hay una run in_progress o waiting, es más útil seguirla directamente:

gh run watch <databaseId> --interval 30        # termina cuando la run acaba; muestra jobs y steps

Útil durante un deploy en curso para ver progreso sin recargar la UI de la plataforma.
