Contenido

Solo usuario: lleva disable-model-invocation: true, asi que el modelo no puede lanzarla por su cuenta ni su descripcion entra en contexto. Se ejecuta solo cuando la invocas con /hv:cicd-init.

Wizard interactivo que escribe el pipeline: no se ejecuta en subagente porque el dialogo con el usuario no sobrevive al aislamiento. El hook pre-cicd-init.js casa con el nombre /hv:cicd-init.

Genera el pipeline de la plataforma configurada (resolve('cicd.platform'): infraestructura.cicd.plataforma del Hilo si existe, si no ecosystem.config.json → cicd.platform; ver .claude/CONFIGURACION.md §Resolución): azure-pipelines.yml (pool configurado (cicd.buildPool) + capability DeployTarget=<env>, Azure DevOps Server o Services) o .github/workflows/*.yml (GitHub Actions: environments, workflow_dispatch on-demand, reusable workflow y composite actions), más los artefactos asociados (runbooks, scripts, docs).

Audiencia: desarrolladores que arrancan CI/CD en un proyecto nuevo o migran de builds Classic (XAML) a YAML.

🧠 Extended Thinking Mode

think hard

Inferir del código fuente (path de .csproj, layout src/docs/testing/, dependencias) tanto como sea posible antes de preguntar al desarrollador. Validar permisos y conectividad con la plataforma (Azure DevOps o GitHub) antes de generar nada. Respetar la fase de adopción elegida (Fase 0/1/2) — cada una genera artefactos distintos.

REGLAS CRÍTICAS

  • Detectar builds Classic (XAML) ANTES de avanzar: si hay TfsBuild/*.xaml, *.xoml o BuildProcessTemplates/ → ABORTAR apuntando a la guía manual skills/cicd-architect/references/classic-migration.md.
  • Respetar los invariantes G1-G19 de .claude/skills/cicd-runtime/SKILL.md. NUNCA emitir features que la plataforma efectiva (resolve('cicd.platform')) (cicd.platform + cicd.variant) no soporte.
  • Idempotencia obligatoria: re-ejecutar en proyecto con instalación previa NO debe romper nada. FASE 0.5 detecta y bifurca.
  • Bifurcar por plataforma: resolve('cicd.platform') = azure-pipelines sigue el camino Azure de siempre (byte a byte); github-actions usa skills/cicd-architect/templates/github/, P3-gh/P4-gh en el wizard, FASE 2.5-gh (environments y secretos por gh) y sellos github-<stack>. none → avisar y no generar pipelines.
  • No tocar el Hub MCP en Fase 0: proyectos sin pipeline no necesitan registro.
  • Backup automático antes de cualquier escritura sobre azure-pipelines.yml o .github/workflows/*.yml pre-existentes.

GitHub Actions cubre .NET SDK-style, Vue y .NET-tool. netfx y Console/Worker siguen solo en Azure Pipelines: necesitan runners Windows self-hosted con IIS o tareas programadas; se añadirán cuando un proyecto los pida.
