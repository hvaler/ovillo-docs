Ovillo technical guides for CI/CD on Azure DevOps (Server on-premise or Services; canonical pattern: a configured pool (cicd.buildPool) with agents told apart by capability, Agent.ComputerName=BUILDAGENT01 for build and DeployTarget=<env> for deploys) and on GitHub Actions (one workflow per entrypoint, environments, on-demand workflow_dispatch). The platform is set by ecosystem.config.json → cicd.platform.

Generated by Ovillo.

About the 08_* numbering

⚠️ The numbering of _patron/ is NOT hierarchical. The order is a reading order (from structural to operational), not a dependency order; 08_CICD/ comes last because it is the most operational.

Recommended flow for a new project

1. Read GUIA_FASES_ADOPCION.md
2. Decide the adoption phase (0, 1 or 2)
3. Run /hv:cicd-init
4. If phase 0: use RUNBOOK_DEPLOY_MANUAL.md
   If phase 1: edit the minimal azure-pipelines.yml (or .github/workflows/ci.yml) that was generated
   If phase 2: use the filled-in RUNBOOK_TEMPLATE.md
5. Before editing the YAML by hand: review your platform's constraints (cicd.variant) or GUIA_GITHUB_ACTIONS.md

Skill + agent + hook

  • Skill cicd-architect — auto-invoked when editing azure-pipelines.yml or .github/workflows/*.yml; proposes fixes according to G1-G19
  • Migrating Classic (XAML) builds (.xaml/.xoml) → YAML: guided by hand through skills/cicd-architect/references/classic-migration.md
  • Agents cicd-pipeline-reviewer (Azure Pipelines) and github-actions-reviewer (GitHub Actions) — YAML audit with a severity per finding
  • Hook pre-cicd-init.js — pre-flight when running /hv:cicd-init: Classic (.xaml) builds on Azure DevOps, gh auth status on GitHub (WARN-first)
