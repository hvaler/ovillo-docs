Guias tecnicas Ovillo para CI/CD sobre Azure DevOps (Server on-premise o Services; patron canonico: pool configurado (cicd.buildPool) con agentes diferenciados por capability, Agent.ComputerName=BUILDAGENT01 para build y DeployTarget=<env> para deploys) y sobre GitHub Actions (workflows por entrypoint, environments, workflow_dispatch on-demand). La plataforma la fija ecosystem.config.json → cicd.platform.

Flujo recomendado para un proyecto nuevo

1. Leer GUIA_FASES_ADOPCION.md
2. Decidir fase de adopcion (0, 1 o 2)
3. Invocar /cicd-init
4. Si Fase 0: usar RUNBOOK_DEPLOY_MANUAL.md
   Si Fase 1: editar azure-pipelines.yml (o .github/workflows/ci.yml) minimal generado
   Si Fase 2: usar RUNBOOK_TEMPLATE.md rellenado
5. Antes de editar el YAML a mano: revisar las restricciones de tu plataforma (cicd.variant) o GUIA_GITHUB_ACTIONS.md

Skill + agent + hook

  • Skill cicd-architect — auto-invocacion al editar azure-pipelines.yml o .github/workflows/*.yml, propone correcciones segun G1-G19
  • Migración de builds Classic (XAML) (.xaml/.xoml) → YAML: manual guiada via skills/cicd-architect/references/classic-migration.md
  • Agents cicd-pipeline-reviewer (Azure Pipelines) y github-actions-reviewer (GitHub Actions) — auditoria YAML con severidad por hallazgo
  • Hook pre-cicd-init.js — pre-flight al invocar /hv:cicd-init: builds Classic (.xaml) en Azure DevOps, gh auth status en GitHub (WARN-first)
