Guía de inicio rápido

Esta guía te permite poner Ovillo en un proyecto en menos de 30 minutos.

3 minlectura
715palabras

Esta guía te permite poner Ovillo en un proyecto en menos de 30 minutos.

Requisitos

  • Claude Code y Node.js ≥ 18 (los hooks son Node).
  • SDK de .NET. Ningún IDE es requisito: la integración con Visual Studio o VS Code se activa por configuración (organization.ide en ecosystem.config.json).
  • git.

Opción A: proyecto existente (recomendado)

Paso 1: instalar el plugin (2 min)

claude plugin marketplace add hvaler/ovillo      # el repositorio es el marketplace
claude plugin install hv@ovillo

Se instala una vez por usuario. A partir de aquí todas las skills se invocan con el prefijo /hv: y los agents como hv:<agent>.

Paso 2: preparar el repositorio (1 min)

cd C:\MiProyecto
claude
/hv:init

/hv:init escribe en el repositorio lo que un plugin no puede llevar, y nunca pisa lo que ya existe:

  • el layout src/ docs/ ops/ _hilo/ _patron/ con sus README;
  • el Hilo (_hilo/, memoria del proyecto) vacío de arranque;
  • el Patrón (_patron/, base de conocimiento de la organización);
  • CLAUDE.md, las 3 reglas incondicionales y la configuración de Claude Code;
  • .vscode/ si organization.ide es vscode, o el script de Solution Folders si es visual-studio.

Si el código vive en la raíz del repositorio, /hv:init lo detecta y propone los git mv a src/; no mueve nada por su cuenta. Con --dry-run muestra el plan sin escribir.

Paso 3: onboarding (10 min)

/hv:onboarding

Configuración guiada en 8 fases: información general, stack, estructura del código, base de datos, integraciones, funcionalidades, tests y documentación, equipo y problemas conocidos. Al terminar deja el Hilo relleno (_hilo/ESTADO_PROYECTO.json, FUNCIONALIDADES.md, DEPENDENCIAS.md, DEUDA_TECNICA.md) y completa el CLAUDE.md.

Paso 4: integración con el IDE (opcional)

Con organization.ide: "visual-studio", el onboarding ejecuta .claude/scripts/integracion-vs.ps1, que añade al .sln un contenedor Ovillo con las carpetas Raiz, _hilo, _patron, docs y ops. Con vscode, /hv:init deja .vscode/settings.json, extensions.json y tasks.json (build, test con cobertura, entorno docker). Con none (valor por defecto) no se toca el IDE.

Paso 5: análisis profundo (opcional)

/hv:analizar

Corre en un subagente aislado y deja los diagramas en docs/architecture/.

Opción B: proyecto nuevo

Paso 1: plugin y repositorio

mkdir C:\MiNuevoProyecto && cd C:\MiNuevoProyecto
git init
claude
/hv:init

Paso 2: crear la solución .NET (3 min)

cd src

dotnet new sln -n MiProyecto

# Clean Architecture
dotnet new webapi   -n MiProyecto.API
dotnet new classlib -n MiProyecto.Application
dotnet new classlib -n MiProyecto.Domain
dotnet new classlib -n MiProyecto.Infrastructure
dotnet new xunit    -n MiProyecto.Tests

dotnet sln add **/*.csproj

dotnet add MiProyecto.API            reference MiProyecto.Application
dotnet add MiProyecto.Application    reference MiProyecto.Domain
dotnet add MiProyecto.Infrastructure reference MiProyecto.Domain
dotnet add MiProyecto.Tests          reference MiProyecto.API

Paso 3: onboarding

claude
/hv:onboarding

Flujo completo

claude plugin install hv@ovillo ──► /hv:init ──► /hv:onboarding ──► (IDE según config) ──► desarrollo
        una vez por usuario         layout,        Hilo relleno,      Solution Folders
                                    Hilo, Patrón   CLAUDE.md          o .vscode/

Configuración de la organización

Copia ecosystem.config.example.json como ecosystem.config.json en la raíz del repositorio y define la identidad de tu organización: prefijo de namespaces, IdP, servicios cloud, motor y nomenclatura de base de datos, plataforma CI/CD, IDE, tema y Hub. Sin ese archivo, Ovillo aplica defaults neutrales. Validación: node .claude/scripts/validate-config.js.

Entorno Docker (5 min)

Revisa y ajusta ops/environment/docker-compose.yml (SQL Server, Redis y el emulador de storage como servicios) y copia .env.example a .env.

Checklist de validación

  • Plugin instalado (claude plugin list muestra hv@ovillo)
  • /hv:init ejecutado: existen src/ docs/ ops/ _hilo/ _patron/ y CLAUDE.md
  • Onboarding completado (/hv:onboarding)
  • IDE integrado si la organización lo configuró
  • Análisis ejecutado (/hv:analizar)
  • Solución .NET compilando
  • Docker funcionando
  • Git inicializado y primer commit (/hv:commit)

Las skills de conocimiento (patrones de API, dominio, tests, seguridad, resiliencia, observabilidad...) se activan solas cuando la petición encaja; las de workflow solo con /hv:.

Solución de problemas

Las carpetas no aparecen en Visual Studio: ejecuta .\.claude\scripts\integracion-vs.ps1 desde la raíz (-Force si hay duplicados). Solo actúa con organization.ide: "visual-studio".

El onboarding no creó los archivos: comprueba _hilo/ESTADO_PROYECTO.json, FUNCIONALIDADES.md, DEPENDENCIAS.md y DEUDA_TECNICA.md; si faltan, repite /hv:onboarding.

Una skill no aparece: claude plugin update hv@ovillo y de nuevo /hv:init. Las skills de workflow no salen en el listado del modelo a propósito; se invocan con /hv:<skill>.

Siguientes pasos

  1. Desarrollar en src/ (código y tests van juntos en la solución).
  2. Configurar el pipeline con /hv:cicd-init (genera ops/cicd/ y ops/testing/).
  3. Documentar la API con /hv:documentacion-tecnica (genera docs/api/).
  4. Preparar el soporte en docs/support/.

Ayuda

  • Estructura del proyecto: README.md
  • Estándares de la organización: _patron/
  • Catálogo de skills: /hv:sos
