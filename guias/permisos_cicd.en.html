CI/CD permissions and infrastructure — TEMPLATE

Status: this is the template for the handoff to the infrastructure team: the inventory of servers, agent pools, capabilities and internal feeds belongs to each organization. /hv:cicd-init writes an adapted copy in ops/cicd/PERMISOS_CICD.md.

What YOUR organization's version has to contain (the structure of the original):

  1. CI/CD platform collection/organization (cicd.platform + URL) and project.
  2. Agent pool(s) — name, type (build vs deploy), servers they run on.
  3. Deploy routing capabilities — a label per agent (e.g. DeployTarget=<env>-<type>), aligned with ecosystem.config.cicd.environments[].deployTarget.
  4. Service account of the agents and the permissions it needs (local deploy, IIS/systemd, backup folders).
  5. Internal package feeds — path or URL reachable FROM the agents (not just from the user network).
  6. Variable groups / secret stores — who creates them, who authorizes pipelines.
  7. Approvers per environment (environments[].approvers) and the platform's environments and gates.
  8. Retention and disk — artifact policy (invariant G10).

/hv:cicd-init derives the real values from the configured pool instead of assuming this document: the template is the list of requests to the infrastructure team, not the runtime's source of truth.

GitHub

On GitHub there is no pool to authorize: the handoff is about permissions on the repository and the organization.
