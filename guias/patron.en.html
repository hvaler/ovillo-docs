Patrón is the knowledge base of the Ovillo ecosystem: the standards, guides and templates of the organization that the skills read in order to generate conforming code and documentation. "Ovillo: you pull the thread following the pattern." The Hilo (_hilo/) is this project's memory; the Patrón is what does not change from one project to the next.

The folder and file names stay in Spanish: the skills point at those exact paths, so they are a contract. Only what you read inside them is translated.

Several documents have an English version (*_EN.md): that is living bilingual documentation, not a leftover. The EDITOR_*.html and GUIA_MARKDOWN.html files are tools for editing the .md with a preview, not documentation.

How it is used

Nobody has to "consult the Patrón" by hand. The skills that need it point at the exact path of the document they read, and the per-layer skills (api, application, domain, infrastructure, database, tests, webapp, blazor, console) activate by themselves when you touch files that match their paths.

There is no index and no catalogue: the skills' triggering by description and by path does that job.

How it is maintained

  • The .md files are the source of truth; the .html files with the same name are their visual render and are regenerated from the .md (ask Claude: "regenerate the HTML from the updated .md").
  • To edit with a preview: open the folder's EDITOR_*.html, edit, save the .md.
  • When the ecosystem is updated, new documents arrive and existing ones are left alone: if the organization has adapted a document, its version is kept.
  • Changing a standard is an architecture decision: record it in the project's _hilo/DECISIONES.md or, if it affects the whole organization, in the ecosystem's repository.

Numbered folders

The 01_…08_ prefixes order the reading (from structural to operational) and collide with nothing: the project root uses src/ docs/ ops/ without numbers. They are kept on purpose.
