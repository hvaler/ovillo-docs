Andamio estándar de proyectos del ecosistema Ovillo.

Un proyecto Ovillo está autocontextualizado: contiene toda la información necesaria para que Claude Code entienda el proyecto y asista en el desarrollo, y la mantiene al día sesión a sesión.

🚀 Instalación rápida

Proyecto existente (recomendado)

# 1. Instalar el plugin (una vez por usuario)
claude plugin marketplace add hvaler/ovillo
claude plugin install hv@ovillo

# 2. Preparar el repositorio
cd C:\MiProyecto
claude
/hv:init          # layout, Hilo, Patrón, CLAUDE.md, configuración; nunca pisa lo existente

# 3. Onboarding guiado
/hv:onboarding

Proyecto nuevo

mkdir C:\MiNuevoProyecto && cd C:\MiNuevoProyecto
git init
claude
/hv:init
dotnet new sln -n MiProyecto -o src      # y los proyectos de la solución
/hv:onboarding

Guía paso a paso: INICIO_RAPIDO.md.

Las skills, los agents y los hooks no viven en el repositorio: los aporta el plugin hv.

Integración con el IDE

Ovillo solo necesita el SDK de .NET. La integración con el IDE depende de organization.ide en ecosystem.config.json:

ValorQué hace
none (por defecto)Nada.
visual-studiointegracion-vs.ps1 añade al .sln un contenedor Ovillo con Raiz, _hilo, _patron, docs y ops.
vscode/hv:init escribe .vscode/ (solución en src, exclusiones de búsqueda, tareas de build, test y docker).
riderSin acciones específicas por ahora.

Si las carpetas no aparecen en Visual Studio: .\.claude\scripts\integracion-vs.ps1 desde la raíz.

Patrón

La carpeta _patron/ contiene las referencias técnicas de la organización: estructura técnica, diseño y usabilidad, consideraciones comunes (normativa, protección de datos, integraciones), plantillas de documentación y SQL, observabilidad, resiliencia y CI/CD. Son la fuente de verdad para las decisiones técnicas y las skills las leen bajo demanda. Un cambio de estándar es una decisión de arquitectura: registrarla en _hilo/DECISIONES.md.

Reglas de desarrollo

  • Todo código generado con IA pasa por code review humano.
  • Sin datos sensibles en prompts (usar placeholders).
  • Secretos en el servicio configurado (cloud.secrets); nunca en el repositorio.
  • Storage y caché distribuidos en infraestructura balanceada; sin estado local.
  • Estrategia de ramas y convención de commits según configuracion.branching del Hilo.

Contacto

  • Dudas técnicas: líder técnico del proyecto
  • Dudas de proceso: jefe de proyecto
  • Soporte del ecosistema: organization.supportEmail de ecosystem.config.json
