Lección 4El flujo de trabajo y la configuración de la organización

1. Instalar el plugin y preparar el repositorio2. Onboarding con /hv:init3. Empezar un proyecto nuevo4. El flujo de trabajo y la configuración de la organización5. Validar la instalación y resolver problemas

Objetivos

  • Ver el flujo completo de una sesión con Ovillo, de la petición al commit
  • Entender qué declara ecosystem.config.json y quién lo lee
  • Levantar el entorno Docker del Hub si tu equipo lo usa

Contenido

Con el proyecto preparado, el día a día es pedir, revisar y confirmar. Esta lección recorre el flujo completo y explica dónde vive la identidad de la organización.

Flujo completo

claude plugin install hv@ovillo ──► /hv:init ──► /hv:onboarding ──► (IDE según config) ──► desarrollo
        una vez por usuario         layout,        Hilo relleno,      Solution Folders
                                    Hilo, Patrón   CLAUDE.md          o .vscode/

Configuración de la organización

Copia ecosystem.config.example.json como ecosystem.config.json en la raíz del repositorio y define la identidad de tu organización: prefijo de namespaces, IdP, servicios cloud, motor y nomenclatura de base de datos, plataforma CI/CD, IDE, tema y Hub. Sin ese archivo, Ovillo aplica defaults neutrales. Validación: node .claude/scripts/validate-config.js.

Entorno Docker (5 min)

Revisa y ajusta ops/environment/docker-compose.yml (SQL Server, Redis y el emulador de storage como servicios) y copia .env.example a .env.

Caso práctico

Abre ecosystem.config.json y cambia cicd.platform. Pide a Claude que te explique cómo desplegaría el proyecto y observa qué comandos propone según la plataforma. Vuelve a dejar el valor original.

Resumen

  • Las skills de conocimiento se activan solas; los workflows, solo con /hv:
  • ecosystem.config.json fija cloud, identidad, base de datos, VCS y CI/CD; el código generado lo respeta
  • El Hub es opcional y opt-in: nadie se registra sin pedirlo
