Lección 5Validar la instalación y resolver problemas

1. Instalar el plugin y preparar el repositorio2. Onboarding con /hv:init3. Empezar un proyecto nuevo4. El flujo de trabajo y la configuración de la organización5. Validar la instalación y resolver problemas

Objetivos

  • Pasar la checklist de validación y saber qué significa cada punto
  • Conocer las skills que más se usan en la primera semana
  • Diagnosticar los tres problemas más frecuentes tras instalar

Contenido

La última lección cierra el círculo: comprobar que todo funciona, saber qué usar primero y dónde mirar cuando algo no va.

Checklist de validación

  • Plugin instalado (claude plugin list muestra hv@ovillo)
  • /hv:init ejecutado: existen src/ docs/ ops/ _hilo/ _patron/ y CLAUDE.md
  • Onboarding completado (/hv:onboarding)
  • IDE integrado si la organización lo configuró
  • Análisis ejecutado (/hv:analizar)
  • Solución .NET compilando
  • Docker funcionando
  • Git inicializado y primer commit (/hv:commit)

Las skills de conocimiento (patrones de API, dominio, tests, seguridad, resiliencia, observabilidad...) se activan solas cuando la petición encaja; las de workflow solo con /hv:.

Solución de problemas

Las carpetas no aparecen en Visual Studio: ejecuta .\.claude\scripts\integracion-vs.ps1 desde la raíz (-Force si hay duplicados). Solo actúa con organization.ide: "visual-studio".

El onboarding no creó los archivos: comprueba _hilo/ESTADO_PROYECTO.json, FUNCIONALIDADES.md, DEPENDENCIAS.md y DEUDA_TECNICA.md; si faltan, repite /hv:onboarding.

Una skill no aparece: claude plugin update hv@ovillo y de nuevo /hv:init. Las skills de workflow no salen en el listado del modelo a propósito; se invocan con /hv:<skill>.

Siguientes pasos

  1. Desarrollar en src/ (código y tests van juntos en la solución).
  2. Configurar el pipeline con /hv:cicd-init (genera ops/cicd/ y ops/testing/).
  3. Documentar la API con /hv:documentacion-tecnica (genera docs/api/).
  4. Preparar el soporte en docs/support/.

Caso práctico

Pasa la checklist en tu proyecto y anota el primer punto que falle. Busca en el portal (Ctrl+K) el hook o la skill implicada y lee su sección «Cuándo no». Escribe en _hilo/LECCIONES.md una línea con lo que has aprendido.

Resumen

  • La checklist comprueba que las skills aparecen, los hooks avisan y el Hilo se actualiza
  • Ante una duda, la ficha de cada skill dice cuándo se activa y cuándo no
  • Si un hook molesta, se baja su política en hooks.policy antes que deshabilitarlo
