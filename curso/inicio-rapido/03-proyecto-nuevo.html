Lección 3Empezar un proyecto nuevo

1. Instalar el plugin y preparar el repositorio2. Onboarding con /hv:init3. Empezar un proyecto nuevo4. El flujo de trabajo y la configuración de la organización5. Validar la instalación y resolver problemas

Objetivos

  • Crear una solución .NET con el layout que Ovillo espera
  • Hacer el onboarding sobre un repositorio vacío
  • Distinguir qué crea dotnet y qué crea Ovillo

Contenido

Cuando el proyecto no existe todavía, Ovillo puede acompañar desde el primer dotnet new. El layout del consumidor es fijo y en inglés a propósito: los hooks y las skills lo conocen.

Paso 1: plugin y repositorio
mkdir C:\MiNuevoProyecto && cd C:\MiNuevoProyecto
git init
claude
/hv:init
Paso 2: crear la solución .NET (3 min)
cd src

dotnet new sln -n MiProyecto

# Clean Architecture
dotnet new webapi   -n MiProyecto.API
dotnet new classlib -n MiProyecto.Application
dotnet new classlib -n MiProyecto.Domain
dotnet new classlib -n MiProyecto.Infrastructure
dotnet new xunit    -n MiProyecto.Tests

dotnet sln add **/*.csproj

dotnet add MiProyecto.API            reference MiProyecto.Application
dotnet add MiProyecto.Application    reference MiProyecto.Domain
dotnet add MiProyecto.Infrastructure reference MiProyecto.Domain
dotnet add MiProyecto.Tests          reference MiProyecto.API
Paso 3: onboarding
claude
/hv:onboarding

Caso práctico

Crea una carpeta vacía, inicializa git y sigue los tres pasos. Al terminar, dibuja el árbol de directorios de primer nivel y marca con una letra quién creó cada carpeta: D para dotnet, O para Ovillo, T para ti.

Resumen

  • El layout src/ docs/ ops/ _hilo/ _patron/ es fijo a propósito; lo ejecutable lo lee de la configuración
  • En un proyecto nuevo el orden es plugin, solución, onboarding
  • docs/architecture/ es el único sitio para la documentación de arquitectura
