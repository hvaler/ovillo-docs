ADR-032Lote K: la columna «próxima versión» de la tercera auditoría

Aceptadoestado
2026-09-08fecha
1519palabras
12 decisionescita
10citada por
  • Estado: Aceptado
  • Fecha: 2026-09-08
  • Contexto: la tercera auditoría externa dejó doce hallazgos para «la próxima versión» (ADR-030 cerró los siete de «ahora»). Se reprodujeron uno a uno sobre 1.0.3 antes de tocar nada. Tres ya estaban resueltos por ADR-027 y ADR-031 y se cierran aquí solo con su evidencia: la paginación generada acota page y size y desempata por Id en el repositorio, que es por donde pasan el controlador y el handler (G-02); las dos superficies de API llevan [ApiVersion] o NewVersionedApi() (G-04); y de los 65 literales en español de las plantillas quedaban cinco en api-integration-patterns (G-03). Los otros nueve seguían vivos:

bash-guard casaba formas concretas sobre el JSON escapado del tool_input, así que rm -r -f, git push -fu y find -delete pasaban con exit 0 mientras rm -rf y git push -f se bloqueaban (H-02). hilo-json-guard solo actuaba en git commit: un Write de {bad a _hilo/ESTADO_PROYECTO.json pasaba con exit 0, con README y ADR-004 prometiendo que «el JSON del Hilo inválido bloquea siempre» (H-03). La doctrina de licencias decía que MediatR era comercial desde la 12 en once sitios mientras recomendaba la 12.4.1, y que Mapperly era MIT en seis; nuget.org dice 12.4.1 Apache-2.0, 13.0.0 con licencia propia, y Mapperly Apache-2.0 (G-05). check-regression.py imprimía «CLEAN (no regression)» con exit 2 cuando no podía comparar nada, y append-run.ps1 escribía engine: desconocido por una variable mal nombrada, así que la serie que ADR-028 daba por conectada no lo estaba (M-03). La puerta de cifras solo casaba «N palabra»: el README publicaba skills · 67, hooks · 21 y «Regla por ruta (12)» con el inventario en 68/22/13, y «puertas» ni se comprobaba porque la clave faltaba en el mapa (M-04). El portal publicaba 74 pares de acentos graves visibles en 18 páginas porque títulos, textos de enlace, asuntos de commit y celdas pasaban por esc() en vez de renderizarse, y md.inline no entendía el delimitador doble (P-01). La página «Datos y privacidad» derivaba sus categorías de una constante escrita a mano (HB-04). El alta del Hub no tenía límite ni token (HB-03). Y toda la lectura del Hub, REST y MCP, es anónima sin que lo diga la documentación que lee quien despliega (HB-02).

Decisión

D1 — bash-guard trabaja sobre el comando en claro y tokeniza los flags

El comando se toma de tool_input.command, no del JSON serializado (el mismo falso negativo por construcción que ADR-026 arregló en los guards de Write). Las letras de todos los grupos de flags cortos del segmento se reúnen (-rf, -r -f, -Rf, -fu), find … -delete cuenta como borrado recursivo, y los targets seguros (node_modules, bin/, obj/, .git/*.lock) y --force-with-lease siguen pasando. test-hooks.js fija dieciocho comandos con su exit.

D2 — hilo-json-guard vigila también Write|Edit, y un hook es un script (enmienda ADR-004 y ADR-009 D1)

El mismo script se cablea en PreToolUse · Write|Edit y valida el contenido que quedaría en disco: en Write, el content; en Edit, el fichero con el reemplazo aplicado. Vacío o sin parsear → exit 2 (bloqueo intrínseco). Para que «22 hooks» siga siendo cierto, el inventario cuenta hooks_cableados como scripts distintos cableados y añade hooks_entradas (evento × script, 23): un script que vigila dos eventos es un hook, no dos. ADR-009 D1 queda enmendado en ese criterio.

D3 — Los hechos de licencia llevan fuente

MediatR: 12.4.1 (2024-09-09) Apache-2.0; 13.0.0 (2025-07-02) con «License Info» propia; última 14.2.0. Riok.Mapperly: Apache-2.0; última 4.3.1. Once «v12+» pasan a «v13+» y seis «MIT» a «Apache-2.0», y las tablas de trampas de licencia enlazan la página de nuget.org de la versión que cambia. La recomendación de MediatR 12.4.1 para código existente deja de contradecir a la doctrina. ADR-026 D7 se corrige en el texto.

D4 — Ningún literal de runtime en español en las plantillas

Los cinco que quedaban (api-integration-patterns: dos logs, dos ErrorMessage, un log de ejemplo) pasan a inglés. scripts/check-crud-templates.js sigue siendo la puerta de compilación; la búsqueda de literales (spanish-literals) se ejecutó como comprobación de cierre y devuelve cero.

D5 — El instrumento de regresión dice cuándo no compara (enmienda ADR-028 D1)

check-regression.py imprime «SIN COMPARACIÓN POSIBLE (arranque en frío…)» y sale con 2 cuando ningún skill tiene dos runs del mismo motor; CI lo muestra como aviso y solo falla con 1 (regresión) o 3 (fichero ilegible). append-run.ps1 escribe el motor real (leía una variable inexistente). La serie tiene ya dos runs comparables (1.0.1 y 1.0.3) y compara las veinte skills. El README deja de publicar un baseline como cifra vigente: remite a la página Evaluaciones y a eval-results-latest.json.

D6 — La puerta de cifras ve las formas que el README usa (enmienda ADR-020)

Además de «N palabra», casa «palabra · N» (diagramas), «por ruta N» y «Regla por ruta (N)», y los números en letra de dos a diez; comprueba también puertas y las reglas por ruta. Sin artículos («una skill» no es una cifra) y sin confundir «15 tools · 4 resources» con «tools · 4». README corregido: 68, 22, 13.

D7 — Convención texto/marcado en el portal, con puerta (enmienda ADR-029)

Dos helpers: H.text() (= md.plain) para <title>, description y atributos; H.rich() (= md.inline) para el cuerpo HTML. Los cambian de sitio: <title>, og:title y description (plano); <h1>, migas, relacionados, anterior/siguiente, hermanos, tarjetas de guías y del Patrón, índice, asunto del último commit, fuente de cada plantilla en Acerca, celdas de privacidad, portada y barra de los decks, y las redirecciones. md.inline resuelve los code spans primero y protegidos, y entiende el delimitador doble ( $ 1). **Puerta nueva en el build**: una página con acentos graves o negritas visibles fuera de <code> y <pre> es error. test-md.js` gana dos casos.

D8 — La página de privacidad deriva las categorías y los datos personales del código (enmienda ADR-024)

Por categoría de mcpSync.categorias: el fichero del Hilo que lee su Parse-<Categoría> en mcp-sync.ps1 y los campos del DTO que acepta el Hub (HiloDecisionItem, NugetItem, MiembroEquipoItem…), leídos de hub/Dtos y FeedbackEndpoints. Los datos personales se declaran junto al dato con [DatoPersonal(finalidad, borrado)] en los modelos del Hub (OwnerAlias, DevAlias, DevEmail, Usuario, NombreCompleto) y la página los lista con su finalidad, si son opcionales y cómo se borran. La constante a mano desaparece.

D9 — El alta del Hub se acota: límite por IP y token opcional (enmienda ADR-007 D5)

/v2/register y /v2/join llevan una política de limitación por IP (Hub:AltaPorMinuto, 10 por defecto; 429 al superarla). Si la organización configura Hub:RegistrationToken, ambos exigen la cabecera X-Hub-Registration-Token con comparación en tiempo constante; sin configurarlo el alta sigue abierta, como hasta ahora, y /v2/version publica registration_token_required. El cliente lo toma de HUB_REGISTRATION_TOKEN. Hub 1.4.0. Ovillo.Hub.Tests fija los tres casos (sin token, con token sin cabecera, límite).

D10 — La lectura del Hub es anónima y se dice donde lo lee quien despliega (enmienda ADR-007 D4)

Toda la superficie de lectura REST (/v2/stats/*, /v2/health/*, /v2/work/*, /v2/team/*, /v2/hilo/stats/*, quality, docs, cicd, feedback) y el endpoint MCP entero responden sin clave: la clave protege las escrituras. ADR-007, hub/README.md y «Datos y privacidad» lo declaran, con la recomendación de un proxy con autenticación si el Hub se publica fuera de la red de confianza, y /v2/version publica read_access: "anonymous". La decisión del mantenedor entre dejarlo así (a) o exigir una clave de lectura opcional Hub:ReadApiKey en esas rutas y en /mcp (b) quedó tomada en ADR-033: (b).

Consecuencias

  • Versión 1.0.4 del ecosistema (correcciones sin cambio de contrato: ninguna clave del Hilo, ningún campo del wire retirado, ningún nombre de invocación). /v2/version gana dos campos y el alta una cabecera opcional.
  • Cambios de comportamiento visibles: bash-guard bloquea variantes que antes pasaban; hilo-json-guard bloquea un Write/Edit que dejaría un JSON inválido en _hilo/; el Hub devuelve 429 a un alta masiva y 401 sin token cuando la organización lo configura.
  • El portal falla el build si vuelve a publicar marcado sin renderizar, y la puerta de cifras cubre el README entero.
  • HB-02: resuelto con la salida (b) en ADR-033 (Hub:ReadApiKey).

Verificación

  • bash-guard: rm -r -f ./bin, git push -fu origin main, find . -name "*.cs" -delete → exit 2 (eran 0); git push --force-with-lease, rm -rf node_modules → 0. hilo-json-guard: Write {bad a _hilo/ESTADO_PROYECTO.json → exit 2 con motivo en stderr (era 0). node scripts/test-hooks.js 52/52.
  • node scripts/build-portal.js: 0 «marcado sin renderizar» (el comprobador externo daba 74 pares en 18 páginas); 0 «cifra a mano» en documentos vivos con el README corregido.
  • python scripts/eval-regression/check-regression.py sobre una serie de un solo run → «SIN COMPARACIÓN POSIBLE», exit 2; sobre la serie real → 20 skills comparadas, exit 0.
  • grep -rn 'v12+' … | grep MediatR → 0; grep 'Mapperly (MIT' → 0. spanish-literals → 0.
  • dotnet test hub/Ovillo.Hub.Tests: registro sin token 201; con token configurado 401 sin cabecera y 201 con ella; tercera alta en un minuto con Hub:AltaPorMinuto=2 → 429. /v2/version → registration_token_required, read_access.
  • privacidad.html: tabla de categorías con los campos del DTO y el fichero del Hilo; tabla de datos personales con cinco filas derivadas de [DatoPersonal]; ninguna constante de prosa en T23.
