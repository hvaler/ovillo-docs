ADR-034Lote L: la columna «puede esperar» de la tercera auditoría

Aceptadoestado
2026-09-09fecha
1047palabras
6 decisionescita
4citada por
  • Estado: Aceptado
  • Fecha: 2026-09-09
  • Contexto: cerradas las columnas «ahora» (ADR-030) y «próxima versión» (ADR-032, ADR-033), quedaban nueve hallazgos menores que la auditoría clasificó como «puede esperar». Se reprodujeron sobre 1.1.0 y los nueve seguían vivos: dos residuos de genealogía («estándar Ovillo v3.7+», «hasta v3.13+») que violan el invariante del constructor; un .pyc y un log de smoke con seis fallos versionados; secret-scanner sin patrones para claves AWS ni JWT y llamando «connection string» a cualquier password = "…"; el Dockerfile del Hub como root, sin HEALTHCHECK y con imágenes base por etiqueta; la tabla de cableado de ADR-004 desfasada y «21 cableados»; 95 páginas del portal con id="contenido" duplicado (el <main> y una sección homónima) más doce con encabezados repetidos, y siete redirecciones sin viewport; run_eval.py --json roto en consolas cp1252; la medida de contexto que asume 0 caracteres para las skills por ruta sin decirlo; y tres idiomas de acceso a datos sin una regla que los ordene.

Decisión

D1 — Ningún número de versión ajeno en el producto (I-03)

Los dos residuos se reescriben sin versión. El invariante «sin genealogía» de la memoria del constructor ya lo exigía; las otras coincidencias de v3.x en el repositorio son ejemplos legítimos (una API en v3.0, release/v3.0, CVSS v3.1).

D2 — Higiene del repositorio (M-07)

scripts/__pycache__/*.pyc sale del índice y __pycache__/ entra en .gitignore. El log smoke-202607.log (seis FAIL, ningún PASS, sin lector) se retira; la salida de un smoke, si se guarda, va junto a los artefactos de su release.

D3 — secret-scanner distingue y cubre más (H-05)

Una password = "…" suelta en código tiene su propio mensaje; «connection string» se reserva para cadenas con Server=, Data Source=, Host=, Initial Catalog= o Database=. Dos patrones nuevos: AWS access key (AKIA + 16 mayúsculas o dígitos) y JWT (tres segmentos base64url con cabecera eyJ, salvo example|placeholder|test). test-hooks.js fija los cuatro casos y el mensaje (57 casos en total).

D4 — El contenedor del Hub, sin root y con salud propia (HB-05)

Imágenes base fijadas por digest además de por etiqueta (las del manifest list del 2026-09-09; para subir la base se cambian las dos cosas a la vez), proceso como el usuario app de la imagen, /data propiedad de ese usuario, y HEALTHCHECK en Dockerfile y docker-compose.yml que ejecuta dotnet Ovillo.Hub.dll --health: el propio binario consulta GET / en el puerto de ASPNETCORE_URLS y sale 0 o 1, porque la imagen runtime no trae curl. Hub 1.5.1. El Dockerfile sigue revisado, no ejecutado con daemon: la deuda 1 de ADR-010 no se cierra aquí.

D5 — ADR-004 apunta a la tabla viva (H-04)

La tabla de cableado del ADR se actualiza al cableado de 1.1.1 y se rotula como la de su fecha: la vigente es la página Hooks del portal, derivada de settings.json. «Los 21 cableados» pasa a 22.

D6 — Ids únicos por página, con puerta (P-02)

El <main> pasa a id="principal" (95 páginas tenían una sección contenido). Las fichas de skill y de agent reservan los ids de sus propias secciones en el Set de ids del renderer, y el informe del agent se renderiza con el mismo Set que el cuerpo, así que un encabezado repetido se numera en vez de duplicarse. Las redirecciones llevan viewport. Puerta nueva en el build: un id repetido en una página es error (una ancla a un id duplicado no sabe adónde va).

D7 — run_eval.py --json en cualquier consola (M-05)

sys.stdout.reconfigure(encoding="utf-8", errors="replace") al entrar en main(). La deuda «run_eval.py --json sigue con traceback» de la memoria del constructor queda cerrada.

D8 — La hipótesis de la medida, dicha (M-06)

La página Contexto declara que las skills por ruta se cuentan a 0 caracteres en el listado porque Claude Code las carga al tocar sus ficheros, y que la documentación oficial no dice si su descripción figura además en el listado.

D9 — Un idioma de acceso a datos (G-06)

Por defecto, un repositorio por agregado con métodos explícitos (I{Entity}Repository en Application, implementación en Infrastructure), que es lo que genera generador-crud y lo que consumen los handlers; el repositorio genérico es una clase base interna, y IQueryable no sale de Infrastructure. Dicho en infrastructure (donde se enseña el genérico) y en application (donde se escribe el handler).

D10 — El plugin instalado no cargaba: el manifiesto no declara hooks/hooks.json (enmienda ADR-006)

Encontrado al instalar hv@ovillo 1.1.0 en un proyecto real: claude plugin list lo marcaba failed to load con «Duplicate hooks file detected: ./hooks/hooks.json resolves to already-loaded file … manifest.hooks should only reference additional hook files». Claude Code carga hooks/hooks.json por convención; la clave hooks del manifiesto es solo para ficheros adicionales, y la referencia al mismo fichero descartaba el plugin entero: ni comandos /hv:*, ni hooks, ni agents. Ni claude plugin validate --strict ni la carga con --plugin-dir lo detectan; solo la instalación desde el marketplace. build-plugin.js deja de emitir la clave y falla si el manifiesto vuelve a llevarla; la comprobación de cierre es la instalación real: claude plugin update hv@ovillo y claude plugin list → enabled.

Consecuencias

  • Versión 1.1.1 (correcciones sin cambio de contrato). Hub 1.5.1 (contenedor y flag --health).
  • El plugin vuelve a cargar: las versiones 1.0.0 a 1.1.0 instaladas desde el marketplace fallaban al arrancar la sesión; 1.1.1 es la primera que un consumidor puede usar tal cual.
  • Dos puertas más estrictas en el portal (ids duplicados) y en el escáner de secretos (más avisos, ninguno bloqueante).
  • Un proyecto que consuma la imagen del Hub verá el proceso sin root y un estado de salud en docker ps.

Verificación

  • grep -rn 'Ovillo v3\|hasta v3' ovillo/ → 0. git ls-files scripts/__pycache__ scripts/smoke-log → 0.
  • secret-scanner por stdin: AKIAIOSFODNN7EXAMPLE → exit 1 «AWS access key»; un JWT → exit 1 «JWT hardcoded»; var password = "abc123" → «password asignada en codigo»; Server=…;Password=… → «Connection string». test-hooks 57/57.
  • dotnet Ovillo.Hub.dll --health sin servidor → exit 1; Ovillo.Hub.Tests 10/10; grep -cE '^USER|^HEALTHCHECK|@sha256' hub/Dockerfile → 4.
  • Portal: 552 páginas, 0 con id duplicado, 0 sin viewport (eran 95 y 7); build en verde con la puerta nueva.
  • python scripts/run_eval.py --json → exit 0 y JSON válido (era UnicodeEncodeError).
