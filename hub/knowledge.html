Tools 7

search_decisions

Busca ADRs (decisiones arquitectonicas) sincronizadas al hub desde todos los proyectos. Filtra opcionalmente por keyword en codigo/titulo/tags. Devuelve top N mas recientes (default 50, max 500).

ParámetroTipoDefaultDescripción
topNint50Maximo de decisiones a devolver. Default 50, max 500.
keywordstring?nullKeyword a buscar en codigo/titulo/tags (case-insensitive). Vacio = sin filtro.

search_lessons

Busca lecciones aprendidas sincronizadas al hub desde todos los proyectos. Filtra opcionalmente por keyword en titulo/categoria/descripcion. Devuelve top N mas recientes (default 50, max 500).

ParámetroTipoDefaultDescripción
topNint50Maximo de lecciones a devolver. Default 50, max 500.
keywordstring?nullKeyword a buscar en titulo/categoria/descripcion (case-insensitive). Vacio = sin filtro.

get_health_summary

Devuelve el resumen de salud tecnica cross-proyecto: nugets totales, vulnerabilidades, deuda tecnica y esfuerzo estimado en dias. Util para dashboards y reports a direccion.

Sin parámetros de usuario.

list_projects

Lista los proyectos registrados en el Hub Ovillo con su ultimo heartbeat, version y hash del ZIP instalado. Util para saber quien esta activo, que version usa, y si tiene los hotfixes aplicados (campo hash_status).

ParámetroTipoDefaultDescripción
topNint100Maximo de proyectos a devolver. Default 100, max 500.
soloActivosboolfalseSi es true, devuelve solo proyectos con heartbeat reciente (<7 dias). Default false.

get_active_workitems

Devuelve los evolutivos (work items) actualmente activos cross-proyecto: estado, prioridad, asignado, fechas. Filtra opcionalmente por developer asignado.

ParámetroTipoDefaultDescripción
asignadoAstring?nullFiltra por developer asignado (alias git). Vacio = todos.

register_decision

Registra una nueva decision arquitectonica (ADR) en el hub para un proyecto especifico. El proyecto debe estar ya registrado (usar list_projects para obtener el ID). Reusable como alternativa a sync Hilo cuando un cliente solo quiere registrar una decision puntual.

ParámetroTipoDefaultDescripción
proyectoIdGuidobligatorioGUID del proyecto registrado en el hub. Obtener de list_projects.
codigostringobligatorioCodigo del ADR (ej: 'ADR-001'). Unique por proyecto.
titulostringobligatorioTitulo de la decision (descriptivo, <200 chars).
estadostring?nullEstado del ADR. Valores tipicos: 'propuesto', 'aceptado', 'rechazado', 'deprecated', 'superseded'. Nullable.
contextostring?nullMarkdown con el contexto / problema que motiva la decision. Nullable.
decisionTextostring?nullMarkdown con la decision tomada. Nullable.
consecuenciasstring?nullMarkdown con las consecuencias (positivas y negativas). Nullable.
fechaDecisionDateTime?nullFecha de la decision (ISO 8601). Nullable, default = ahora server-side.
tagsstring?nullTags separados por coma (ej: 'mcp,sdk,refactoring'). Nullable.
devAliasstring?nullAlias git del developer que registra la decision (multi-dev attribution). Nullable.

register_lesson

Registra una nueva leccion aprendida en el hub para un proyecto especifico. El proyecto debe estar ya registrado (usar list_projects para obtener el ID). Util cuando Claude detecta un patron o anti-patron durante una sesion y quiere persistirlo cross-proyecto.

ParámetroTipoDefaultDescripción
proyectoIdGuidobligatorioGUID del proyecto registrado en el hub. Obtener de list_projects.
titulostringobligatorioTitulo de la leccion (descriptivo, <200 chars).
descripcionstringobligatorioDescripcion en Markdown. Incluye contexto, problema observado, solucion aplicada y aprendizaje generalizable.
categoriastring?nullCategoria libre. Valores tipicos: 'sql', 'devops', 'hooks', 'security', 'performance'. Nullable.
severidadstring?nullSeveridad del aprendizaje. Valores tipicos: 'info', 'warning', 'critical'. Nullable.
fechaAprendizajeDateTime?nullFecha en que se aprendio la leccion (ISO 8601). Nullable, default = ahora server-side.
devAliasstring?nullAlias git del developer que registra la leccion. Nullable.

Lecturas por URI, comunes a todos los grupos.

URINombreMIMEDescripción
ovillo://decisions/{proyecto}/{codigo}decisiontext/markdownDevuelve el texto completo en Markdown de una ADR (Architecture Decision Record) registrada en el hub: contexto, decision, consecuencias, estado y tags.
ovillo://lessons/{proyecto}/{id}lessontext/markdownDevuelve el texto completo en Markdown de una leccion aprendida del hub: titulo, categoria, descripcion y severidad. El proyecto en la URI es informativo; el id es el identificador real.
ovillo://snapshots/{proyecto}/{categoria}snapshottext/markdownDevuelve el snapshot Hilo mas reciente de una categoria (decisiones, lecciones, funcionalidades, dependencias, historial, contexto_tecnico) para un proyecto. Util para que Claude lea el estado actual del proyecto sin tener que cargar cada decision individualmente.
ovillo://projects/{nombre}/statusproject-statustext/markdownDevuelve la ficha de estado de un proyecto registrado en el hub: heartbeat, version del ecosistema, evolutivos en progreso, ultimas decisiones. Util para retomar contexto de un proyecto desconocido o validar que esta activo.

Prompts 3

PromptParámetrosDescripción
/audit-security—Genera un prompt de auditoria de seguridad cross-proyecto con los datos vivos del hub: nugets vulnerables, vulnerabilidades criticas y deuda tecnica alta. El modelo debe priorizar acciones y proponer remediacion.
/review-project-decisionsproyectoGenera un prompt para revisar las ADRs aceptadas de un proyecto especifico, detectando incoherencias entre decisiones, decisiones que ya no aplican o gaps de documentacion. El modelo debe analizar las ADRs sincronizadas en el hub.
/weekly-status-report—Genera un prompt para producir el informe semanal del ecosistema Ovillo: proyectos activos, evolutivos en curso, decisiones recientes y carga por developer. El modelo redacta un resumen ejecutivo y operativo.

Conectar

El consumidor declara el Hub en ecosystem.config.json → hub (opt-in, deshabilitado por defecto) y autentica con la cabecera X-Hub-Api-Key. La skill hub-client es el cliente de referencia; /hv:mcp-register registra el proyecto (nunca en silencio). Despliegue y contratos: Ovillo.Hub.

{
  "hub": {
    "enabled": false,
    "url": "",
    "auth": "apikey",
    "apiKeyHeader": "X-Hub-Api-Key",
    "registerOnInstall": false
  }
}
ClaveTipoDefaultQué hace
hub.enabledbooleanfalse
hub.urlstring""URL base del Hub (ej. http://localhost:8080 con el docker-compose del Hub).
hub.authstring"apikey"
hub.apiKeyHeaderstring"X-Hub-Api-Key"Nombre del header de API key.
hub.registerOnInstallbooleanfalseSi el instalador registra el proyecto en el Hub. SIEMPRE opt-in explicito: ningun instalador ni hook registra en silencio.
