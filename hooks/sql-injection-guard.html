Qué comprueba

Salida: hallazgos y motivo del bloqueo por stderr, que es lo que Claude Code muestra con exit 1 y 2 (stdout solo es contexto en SessionStart y UserPromptSubmit; ADR-004 D1 enmendado por ADR-030) WARN-first: el .ps1 v1.0.0 salia siempre 0 (avisos, el dev decide); en el port, con hallazgos resolvePolicy(cfg, 'sql-injection-guard') decide exit 1 (warn, default) o exit 2 (block) segun ecosystem.config -> hooks.policy / hooks.blockList. Los patrones se aplican sobre el contenido REAL del tool_input (h.getNewContent, que des-escapa). Antes se casaban sobre el JSON serializado y una interpolacion llegaba como $\" : falsos negativos por construccion.

Política

WARN-first: avisa (exit 1) por defecto y bloquea (exit 2) solo si la organización lo pone en hooks.blockList o sube hooks.policy a block.

ClaveTipoDefaultQué hace
hooks.policystring"warn"WARN-first por defecto (avisan sin bloquear); 'block' eleva todos los hooks defensivos a bloqueo. Los hooks intrinsecamente BLOCK (bash-guard, protect-files certs/keys, hilo-json-guard) no se degradan nunca.
hooks.blockListarray[]Hooks concretos elevados a BLOCK aunque policy=warn (ej. ['secret-scanner']).

#!/usr/bin/env node
// sql-injection-guard.js - Detectar SQL inseguro en codigo C#
// Evento: PreToolUse[Write|Edit] (para que exit 2 pueda impedir la escritura)
// Exit 0 = sin hallazgos · Exit 1 = AVISO (politica warn) · Exit 2 = BLOCK (politica block)
// Salida: hallazgos y motivo del bloqueo por stderr, que es lo que Claude Code muestra con exit 1 y 2 (stdout solo es
//         contexto en SessionStart y UserPromptSubmit; ADR-004 D1 enmendado por ADR-030)
// Version: 1.0.0
//   WARN-first: el .ps1 v1.0.0 salia siempre 0 (avisos, el dev decide); en el port,
//   con hallazgos resolvePolicy(cfg, 'sql-injection-guard') decide exit 1 (warn,
//   default) o exit 2 (block) segun ecosystem.config -> hooks.policy / hooks.blockList.
//   Los patrones se aplican sobre el contenido REAL del tool_input (h.getNewContent, que
//   des-escapa). Antes se casaban sobre el JSON serializado y una interpolacion llegaba como
//   $\" : falsos negativos por construccion.

'use strict';

const h = require('./lib/helpers');
const cfgLib = require('./lib/config');

function main() {
  const hookData = h.readHookInput();

  // Solo archivos .cs
  const filePath = h.getFilePath(hookData) || '';
  if (!/\.cs$/i.test(filePath)) return 0;

  // Contenido REAL, ya des-escapado (h.getNewContent). Casar los patrones sobre el JSON
  // serializado daba falsos negativos por construccion: una interpolacion llega como $\" y
  // ningun patron escrito contra la comilla sin escapar la ve.
  const content = h.getNewContent(hookData);
  if (!content) return 0;

  let warnings = 0;

  // === PATRONES SQL INSEGURO ===

  // FromSqlRaw con interpolacion de string
  if (/FromSqlRaw\s*\(\s*\$"/i.test(content) || /FromSqlRaw\s*\(\s*"[^"]*"\s*\+/i.test(content)) {
    console.error('SQL INJECTION: FromSqlRaw con interpolacion/concatenacion. Usar FromSqlInterpolated o parametros.');
    warnings++;
  }

  // ExecuteSqlRaw con interpolacion
  if (/ExecuteSqlRaw\s*\(\s*\$"/i.test(content) || /ExecuteSqlRaw\s*\(\s*"[^"]*"\s*\+/i.test(content)) {
    console.error('SQL INJECTION: ExecuteSqlRaw con interpolacion. Usar ExecuteSqlInterpolated.');
    warnings++;
  }

  // SqlCommand con concatenacion
  if (/SqlCommand\s*\(\s*"[^"]*"\s*\+/i.test(content) || /CommandText\s*=\s*"[^"]*"\s*\+/i.test(content)) {
    console.error('SQL INJECTION: SqlCommand con concatenacion de string. Usar SqlParameter.');
    warnings++;
  }

  // EXEC con concatenacion en string SQL
  if (/EXEC\s*\(\s*'[^']*'\s*\+|EXEC\s*\(\s*"[^"]*"\s*\+/i.test(content)) {
    console.error('SQL INJECTION: EXEC con concatenacion. Usar sp_executesql con parametros.');
    warnings++;
  }

  // string.Format en queries SQL
  if (/string\.Format\s*\(.*SELECT|string\.Format\s*\(.*INSERT|string\.Format\s*\(.*UPDATE|string\.Format\s*\(.*DELETE/i.test(content)) {
    console.error('SQL INJECTION: string.Format en query SQL. Usar parametros.');
    warnings++;
  }

  if (warnings > 0) {
    const policy = cfgLib.resolvePolicy(cfgLib.load(), 'sql-injection-guard');
    console.error('');
    console.error(`Se detectaron ${warnings} patron(es) de SQL injection potencial.`);
    console.error('Referencia: OWASP A03:2021 - Injection');
    console.error('Solucion: Usar siempre parametros (@param) o FromSqlInterpolated.');
    console.error(`Politica: ${policy} (ecosystem.config hooks.policy)`);
    return policy === 'block' ? 2 : 1;
  }

  return 0;
}

try {
  process.exit(main());
} catch (e) {
  console.error(`sql-injection-guard: error inesperado (${e.message}) - no se bloquea el flujo`);
  process.exit(0);
}
