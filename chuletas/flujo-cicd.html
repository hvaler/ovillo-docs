Flujo CI/CD con Ovillo

Los cuatro comandos /hv:cicd-* se bifurcan solos según cicd.platform. Esta chuleta recoge el camino feliz y dónde mirar cuando algo falla.

De autor: publicacion/src/chuletas/flujo-cicd.md, se revisa con cada versión.

Los cuatro comandos /hv:cicd-* se bifurcan solos según cicd.platform. Esta chuleta recoge el camino feliz y dónde mirar cuando algo falla.

1 · Declarar la plataforma

En ecosystem.config.json:

{ "cicd": { "platform": "github-actions", "environments": ["dev", "pre", "pro"] } }

azure-pipelines o github-actions. El agente de build se declara en cicd.buildAgent.

2 · Generar el pipeline

ComandoQué hace
/hv:cicd-initwizard por fases: detecta stack, entrypoints y ramas; materializa ops/cicd/
/hv:cicd-init (de nuevo)vuelve a sellar las plantillas sin pisar lo tuyo

Antes de empezar, pre-cicd-init comprueba gh auth status o el PAT de Azure DevOps: avisa, no bloquea.

3 · Ver el estado

/hv:cicd-status muestra las últimas ejecuciones con rama, resultado y enlace.

  • GitHub: gh run list y gh run view
  • Azure DevOps: API de builds

4 · Versionar y construir

/hv:cicd-release sube la versión (SemVer), crea el tag v* y las notas de la release. El tag dispara la CI; la protección de v* exige firma e historial lineal.

5 · Desplegar bajo demanda

/hv:cicd-deploy pre lanza el workflow de despliegue con el environment elegido (gh workflow run … -f environment=pre o su equivalente en Azure DevOps). pre y pro piden aprobación de revisores.

Puertas del pipeline

  • Build: restore, build, test con cobertura.
  • Security: escaneo de vulnerabilidades NuGet y secretos, después la puerta que decide.
  • Coverage: coverage-gate.ps1 -Mode warn|block lee Cobertura u OpenCover y compara con el umbral.
  • Quality: si hub.enabled, publica los resultados en el Hub.

Si algo falla

SíntomaMira
Can't find action.yml en el job de deployfalta el checkout parcial de .github/actions
push de workflows rechazadoel token necesita el scope workflow
el environment no pide aprobaciónlos revisores de environment dependen del plan del repo
las anotaciones no aparecen##vso es de Azure DevOps; en GitHub es ::warning::
