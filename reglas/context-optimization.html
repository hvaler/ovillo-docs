Regla: Optimizacion de contexto y tokens

siempre (sin paths)carga
≈ 567 tokenscoste
351palabras
/hv:initla escribe
2026-09-08último cambio

Se aplica SIEMPRE. Cada fichero leido, cada salida de comando y cada mensaje gastan ventana. /context dice el modelo activo y el uso real: comprobarlo, no deducirlo del nombre del modelo. Ventanas por familia, umbrales y por que de cada regla: _patron/SISTEMA_CONTEXTO_CLAUDE.md.

Lectura

  • No releer un fichero ya leido en la sesion, salvo que el usuario lo haya cambiado a mano.
  • Fichero largo: Grep primero, y offset/limit para leer solo la seccion que importa.
  • Nunca leer binarios, imagenes ni PDF completos para sacar metadatos. Config (JSON, YAML) solo si se va a modificar.
  • No releer CLAUDE.md: ya esta en el contexto.

Busqueda

  • Glob en vez de find o ls -R; Grep en vez de grep/rg por Bash; Read en vez de cat; Edit en vez de sed.
  • Acotar: head_limit; output_mode: "files_with_matches" para saber donde esta; "count" para saber cuantas.
  • Un Grep con la regex combinada en vez de varios seguidos.

Subagentes

  • Delegar al Agent lo verbose: busquedas de varias rondas, lectura de muchos ficheros, tests o builds con salida extensa, analisis de logs. Devuelve un resumen y no gasta el contexto principal.
  • Agent(subagent_type="Explore", prompt="Busca los ficheros que usan ILogger en src/"). Los agents del ecosistema (hv:<agent>) ya trabajan asi: cada uno en su propio contexto.

Salida

  • Acotar Bash: | head -20, dotnet build -v quiet, dotnet test --verbosity minimal --no-build, git status --short, git log --oneline -5, y git diff --stat antes de un diff completo.
  • No hacer echo para confirmar lo que la herramienta ya devuelve, ni listar un directorio para comprobar un fichero (test -f fichero).

Compactacion

  • Sugerir /compact al final de una respuesta, nunca interrumpiendo: tras completar una tarea grande, antes de empezar otra no relacionada, o al pasar los umbrales de tool calls y de ficheros leidos de la ventana activa.
  • Tres errores de build seguidos: parar y replantear en vez de insistir.
  • Al compactar, el resumen debe conservar: evolutivo activo, ficheros modificados en la sesion, decisiones tomadas y proximos pasos.
