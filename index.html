Ovillo

Ecosistema de desarrollo asistido por IA para proyectos .NET, construido sobre Claude Code y distribuido como plugin. Skills que Claude aplica solas, workflows que solo lanzas tú, hooks que avisan antes de romper nada y una memoria del proyecto que sobrevive a la sesión.

Instalar

claude plugin marketplace add hvaler/ovillo
claude plugin install hv@ovillo
/hv:init          # en la raíz del repo del proyecto

El repositorio del ecosistema es de acceso por invitación. Estas órdenes funcionan cuando la cuenta que las ejecuta tiene acceso concedido: el marketplace de un plugin es el propio repositorio. Para pedirlo, abre una incidencia en el repositorio de esta documentación. Esta página, las guías y las fichas son públicas y completas: describen el ecosistema entero, no una demo.

Actualizar: claude plugin update hv@ovillo y volver a ejecutar /hv:init, que solo añade lo que falte. Detalle en Instalación y primer uso; versiones y hashes en Versiones.

Qué garantiza

  • Nada se activa a tus espaldas: los workflows con efectos (commits, despliegues, scaffolding) solo se ejecutan cuando los invocas con /hv:. La release comprueba que cada workflow lleva el flag que lo impide y el hook skill-guard lo revisa en cada sesión.
  • Avisa antes de bloquear: los hooks son WARN-first; solo tres bloquean siempre, y son los que evitan daño irreversible.
  • Todo lo que ves aquí sale del código: el portal se genera del repositorio en cada versión. Las puertas de la release comprueban enlaces, páginas huérfanas, cifras escritas a mano frente al inventario, coherencia de la página de evaluaciones y el manifiesto de páginas; si algo no cuadra, la release no sale.
  • Calidad medida, no prometida: la página de evaluaciones publica precisión, recall y F1 del disparo de las skills de conocimiento (qué petición activa qué skill). Mide la activación, no el resultado de la ejecución.
  • Tu organización, tus decisiones: proveedor cloud, identidad, base de datos, VCS y CI/CD se declaran en un fichero y el código generado los respeta.
  • Memoria y conocimiento: el Hilo guarda el estado del proyecto entre sesiones; el Patrón, los estándares de tu equipo.
